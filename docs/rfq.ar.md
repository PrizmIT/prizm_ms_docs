# طلبات التسعير (RFQ)

تُدير وحدة **طلبات التسعير (RFQ)** دورة التوريد الكاملة — بدءاً من إنشاء الطلبات المرتبطة بالاستفسارات الفنية، مروراً بدعوة الموردين عبر البريد الإلكتروني، وجمع عروض الأسعار، والمقارنة، والتقييم، وحتى الترسية النهائية. تتكامل الوحدة بعمق مع واجهة Microsoft Graph API لإدارة البريد الإلكتروني وتتضمن ميزات ذكاء اصطناعي لمعالجة عروض الأسعار تلقائياً.

---

## الوصول إلى الوحدة

انتقل إلى **RFQ** من القائمة الجانبية. تحتوي الوحدة على الأقسام الفرعية التالية:

| القائمة الفرعية | الوصف |
|----------|-------------|
| **لوحة المعلومات** | إحصائيات وأداء المستخدمين وتحليلات الموردين |
| **RFQ** | قائمة الطلبات الرئيسية — إنشاء وتعديل وإرسال وتتبع |
| **عناصر RFQ** | العناصر المرتبطة بالطلبات من الاستفسارات الفنية |
| **العناصر** | كتالوج العناصر الرئيسي وعناصر ورقة المقارنة |
| **رسائل RFQ** | رسائل ردود الموردين المسحوبة عبر Microsoft Graph API |
| **قائمة انتظار التسعير الذكي** | قائمة استخراج عروض الأسعار بالذكاء الاصطناعي |
| **بريد المشتريات** | صندوق البريد العام للمشتريات (رسائل غير مرتبطة بـ RFQ) |
| **البريد الإلكتروني** | عارض بريد إلكتروني مدمج لصندوق المشتريات |
| **تقرير مؤشرات الأداء** | لوحات أداء موظفي المشتريات |
| **ورقة المقارنة** | مقارنة عروض الموردين جنباً إلى جنب |
| **التقارير** | تقارير الردود والإجراءات |
| **الإعدادات** | إعدادات RFQ (للمسؤولين فقط) |

---

## لوحة المعلومات

توفر لوحة معلومات RFQ نظرة شاملة لحظية على نشاط المشتريات.

### نظرة عامة على الإحصائيات

- **الطلبات المعلقة** — عدد الطلبات بانتظار إجراء
- **الطلبات المقبولة** — عدد الطلبات النشطة
- **عروض الأسعار** — إجمالي العروض المستلمة
- **زمن استجابة الموردين** — متوسط وقت الرد
- **الاتجاهات الشهرية** — رسوم بيانية للطلبات والردود والعروض والإجراءات شهرياً

### أداء المستخدمين

مقاييس أداء لكل مسؤول مشتريات:

- الطلبات المنشأة (إجمالي وشهري)
- ردود الموردين المستلمة
- عروض الأسعار المعالجة
- الإجراءات المتخذة
- الردود التي تحتاج إجراء
- إحصائيات الطلبات النشطة

### تحليلات الموردين

أداء كل مورد على حدة:

- الطلبات المرسلة للمورد
- توزيع الطلبات المقبولة/المعلقة
- إجمالي الردود وعروض الأسعار
- أوامر الشراء المولدة
- تتبع زمن الاستجابة
- اتجاهات النشاط الشهري

### تصفية الفترات

- اليوم، هذا الأسبوع، الأسبوع الماضي، هذا الشهر، الشهر الماضي
- نطاق تاريخ مخصص

---

## قائمة RFQ

تعرض الواجهة الرئيسية جميع الطلبات في جدول AG Grid تفاعلي.

### الأعمدة الرئيسية

- **رمز RFQ** — رقم مرجعي فريد (مثال: RFQ-24000067)
- **موضوع البريد** — سطر الموضوع المستخدم في التواصل مع الموردين
- **الحالة** — حالة دورة الحياة (مسودة، معلق، نشط/مقبول، مغلق، مؤرشف)
- **المشروع المرتبط** — المشروع أو مصدر الميزانية
- **المالك** — مسؤول المشتريات المعين
- **حالة ردود الموردين** — الردود المستلمة / الموردين المدعوين
- **تاريخ الإنشاء** و**تاريخ الاستحقاق**

### الإجراءات

- **إنشاء RFQ** — بدء طلب تسعير جديد
- **عرض/تعديل** — فتح تفاصيل الطلب
- **حذف** — حذف مؤقت مع تسجيل النشاط
- **إرسال للموردين** — الإرسال عبر البريد الإلكتروني
- **جلب الرسائل** — سحب أحدث ردود الموردين من Microsoft Graph API

---

## إنشاء طلب تسعير

### الخطوة 1: اختيار العناصر

تأتي العناصر من **الاستفسارات الفنية**. حدد عنصراً أو أكثر لتضمينه في الطلب.

### الخطوة 2: اختيار الموردين

اختر الموردين من قائمة الموردين المعتمدين. يتم تحميل جهات اتصال كل مورد تلقائياً.

### الخطوة 3: إعداد تفاصيل الطلب

- **الموضوع** — وصف واضح لما يتم تسعيره
- **المشروع المرتبط** — الربط بمشروع
- **المالك** — تعيين مسؤول المشتريات
- **تاريخ الاستحقاق** — الموعد النهائي لرد الموردين
- **نوع الطلب** — مورد (مواد) أو خدمة

### الخطوة 4: إعدادات البريد الإلكتروني

- **موضوع البريد** — سطر الموضوع لرسالة الدعوة
- **المرسل** — اختيار الجهة المرسلة (بريزم إنرجي أو المنشور للمقاولات)
- **قالب البريد** — قالب محدد مسبقاً أو مخصص

### الخطوة 5: الشروط والملاحظات

- **ملاحظات عامة** — مرئية للموردين في الدعوة
- **ملاحظات داخلية** — لفريق المشتريات فقط
- **الشروط والأحكام** — الشروط التجارية

### الخطوة 6: الحفظ أو الإرسال

- **حفظ كمسودة** — المتابعة لاحقاً
- **إرسال** — الإرسال لجميع الموردين المحددين عبر Microsoft Graph API

!!! info "رمز RFQ"
    يُعيَّن لكل طلب رمز فريد (مثال: RFQ-24000067) يُضمَّن في جميع عناوين البريد الإلكتروني. يستخدم النظام هذا الرمز لمطابقة ردود الموردين تلقائياً مع الطلب الصحيح.

---

## مراحل وحالات RFQ

| الحالة | الوصف |
|--------|-------------|
| **مسودة** | قيد الإعداد؛ قابلة للتعديل الكامل؛ غير مرئية للموردين |
| **معلق** | بانتظار الموافقة الداخلية أو معلومات إضافية |
| **مقبول/نشط** | أُرسل للموردين؛ بانتظار الردود؛ الحقول الأساسية مقفلة |
| **منتهي** | انتهى الموعد النهائي؛ يمكن التمديد أو الإغلاق |
| **مغلق** | تم ترسية المورد؛ تم التحويل إلى أمر شراء أو عقد |
| **مؤرشف** | محفوظ للرجوع إليه؛ للقراءة فقط |

!!! warning "قفل الحقول"
    بمجرد إرسال RFQ (الحالة النشطة)، تُقفل الحقول الأساسية لضمان المقارنة العادلة بين جميع الموردين. يمكن تعديل الحالة والملاحظات الداخلية فقط.

---

## دعوات الموردين وتكامل البريد الإلكتروني

### إرسال الدعوات

تُرسل الدعوات عبر **Microsoft Graph API** باستخدام حسابات البريد الإلكتروني المُعدّة:

- **بريزم إنرجي** — procurement@prizm-energy.com
- **المنشور للمقاولات** — procurement@almanshour.com

تتضمن كل دعوة رمز RFQ في سطر الموضوع وتفاصيل العناصر والمواصفات والموعد النهائي للرد وتعليمات التقديم.

### الجلب التلقائي للردود

يقوم النظام بتشغيل **مهمة مجدولة** تلقائياً:

1. الاتصال بـ Microsoft Graph API
2. جلب الرسائل الجديدة من صندوق بريد المشتريات
3. مطابقة الردود مع الطلبات عبر **رمز RFQ في سطر الموضوع**
4. تصفية الرسائل الداخلية (@prizm-energy.com، @almanshour.com)
5. استبعاد إشعارات الارتداد (رسائل فشل التسليم)
6. تخزين ردود الموردين الصالحة مع المرفقات

### تتبع الردود

يتتبع النظام لكل مورد:

- طابع وقت إرسال الدعوة
- الردود المستلمة (العدد والمحتوى)
- المرفقات المرفوعة
- زمن الاستجابة
- الإجراءات المتخذة على الردود

## عناصر RFQ

تأتي عناصر RFQ من **الاستفسارات الفنية** وتحدد ما يتم تسعيره.

### حقول العنصر

- **معرف العنصر** و**اسم العنصر** — معرف فريد واسم مختصر
- **الاسم الكامل للعنصر** — الاسم الوصفي الكامل
- **مرجع الاستفسار الفني** — الاستفسار المصدري
- **الكمية** و**وحدة القياس**
- **المواصفات** و**المتطلبات**

---

## ورقة المقارنة

توفر ورقة المقارنة مقارنة منظمة جنباً إلى جنب لعروض أسعار الموردين.

### الميزات

- عرض جميع عروض الموردين لنفس العنصر في جدول واحد
- مقارنة الأسعار وشروط التسليم والأحكام
- إبراز أقل سعر أو أفضل قيمة
- إضافة ملاحظات تقييم داخلية
- تتبع تفاصيل العناصر عبر طلبات متعددة

---

## قائمة انتظار التسعير الذكي

تُؤتمت **قائمة انتظار التسعير الذكي** استخراج عروض الأسعار من رسائل ردود الموردين.

### كيف يعمل

1. يتم جلب وتخزين ردود الموردين
2. يعالج الذكاء الاصطناعي محتوى البريد والمرفقات
3. يتم استخراج بيانات العرض (الأسعار، الكميات، الشروط)
4. توضع البيانات المستخرجة في قائمة المراجعة البشرية
5. البيانات المعتمدة تُحدّث مصفوفة المقارنة

---

## بريد المشتريات

رسائل البريد الإلكتروني العامة للمشتريات غير المرتبطة بطلب RFQ محدد.

### الميزات

- جلب من Microsoft Graph API
- تصفية الرسائل الداخلية ورسائل الارتداد
- الربط بجهات اتصال الموردين عند الإمكان
- البحث حسب الموضوع أو اسم المورد أو جهة الاتصال
- تتبع الحالة (معلق/معالج)

---

## تقرير مؤشرات الأداء (KPI)

لوحات أداء الموظفين لفريق المشتريات.

### المقاييس المتتبعة

- **الطلبات المنشأة** — لكل مستخدم وفترة
- **الردود المستلمة** — تتبع استجابة الموردين
- **العروض المعالجة** — العروض المحولة
- **الإجراءات المتخذة** — نشاط المستخدم على الردود
- **زمن الاستجابة** — متوسط وقت التعامل مع الردود

### العروض

- **مؤشرات أداء القسم** — نظرة عامة على جميع مستخدمي المشتريات
- **مؤشرات أداء المستخدم** — لوحة تفصيلية فردية
- **مؤشرات أداء المشتريات** — مقاييس خاصة بالمشتريات
- **مؤشرات أداء الموظف** — لكل موظف مع سياق المدير

## محرك RFQ (الإصدار 2)

**محرك RFQ** هو خط أنابيب مدعوم بالذكاء الاصطناعي يُؤتمت عملية RFQ بمنهج "النظام يُنفذ، الإنسان يُراجع".

### مراحل خط الأنابيب

| المرحلة | الوصف |
|---------|-------------|
| **الاستقبال** | النظام يكتشف العناصر المحددة ويقترح تجميع RFQ |
| **الصياغة** | الذكاء الاصطناعي يصيغ محتوى الطلب (العنوان، الوصف، الشروط) |
| **المطابقة** | النظام يوصي بالموردين المناسبين |
| **الموافقة** | مراجعة بشرية نهائية قبل الإرسال |
| **الإرسال** | النظام يرسل الرسائل عبر Microsoft Graph API |
| **التتبع** | النظام يراقب ردود الموردين |
| **الاستلام** | تصنيف الردود واستخراج عروض الأسعار |
| **المقارنة** | توليد مصفوفة المقارنة تلقائياً |
| **الترسية** | اختيار الفائز بمراجعة بشرية |
| **الإغلاق** | اكتمال دورة حياة RFQ |

### المهام المؤتمتة

يُشغّل محرك RFQ ثلاث مهام خلفية تلقائية:

1. **الاستقبال التلقائي** — اكتشاف العناصر المحددة واقتراح تجميعات RFQ
2. **التتبع التلقائي** — جلب ردود الموردين من Microsoft Graph API
3. **التذكير التلقائي** — إرسال تذكيرات للمواعيد القريبة أو المتجاوزة

## التكامل مع الوحدات الأخرى

| الوحدة | التكامل |
|--------|-------------|
| **الاستفسارات الفنية** | إنشاء تلقائي عند تغيير حالة الاستفسار؛ العناصر مصدرها الاستفسارات |
| **المشاريع** | تبويب RFQ في عرض المشروع؛ ربط الطلبات بالمشاريع |
| **المشتريات** | تحويل الطلبات المرسى عليها إلى أوامر شراء |
| **الموردين** | جهات الاتصال وتتبع العروض وتحليلات الاستجابة |
| **العملاء المحتملين** | تكامل بيانات الموردين والعملاء |
| **Microsoft Graph** | إرسال واستقبال البريد للدعوات وجلب الردود |

## الصلاحيات

### صلاحيات RFQ

| الوحدة | الصلاحيات |
|--------|------------|
| **RFQ** | عرض (عام)، عرض خاص، إجراء، تغيير الحالة، تغيير التفعيل، إنشاء، تعديل، تحويل، حذف |
| **عناصر RFQ** | عرض (عام)، عرض خاص، تعديل، حذف |
| **رسائل RFQ** | عرض (عام)، عرض خاص، تعديل، حذف |
| **تقارير RFQ** | عرض (عام)، عرض خاص، تعديل، حذف |

!!! tip "صلاحيات المسؤول"
    قائمة **الإعدادات** مرئية فقط للمسؤولين. تشمل إعدادات RFQ وقوالب البريد الإلكتروني وإدارة الكلمات المفتاحية.

## البحث الشامل

وحدة RFQ متكاملة بالكامل مع البحث الشامل على مستوى النظام. يمكنك البحث عبر:

- **طلبات RFQ** — برمز الطلب أو موضوع البريد
- **عناصر RFQ** — باسم العنصر أو الاسم الكامل
- **رسائل RFQ** — بالموضوع أو اسم جهة الاتصال أو رمز RFQ
- **بريد المشتريات** — بالموضوع أو اسم المورد/جهة الاتصال
- **ورقة المقارنة** — باسم العنصر أو الاسم الكامل

---

## أفضل الممارسات

- **حدد العناصر بوضوح** في الاستفسارات الفنية قبل إنشاء الطلبات — المواصفات التفصيلية تقلل استفسارات الموردين
- **ادعُ 3-5 موردين** للحصول على أسعار تنافسية
- **راقب قائمة انتظار التسعير الذكي** بانتظام لمراجعة واعتماد البيانات المستخرجة
- **استخدم ورقة المقارنة** قبل اتخاذ قرارات الترسية — توفر عرضاً منظماً لجميع العروض
- **راجع تقارير مؤشرات الأداء** أسبوعياً لتتبع إنتاجية الفريق وتحديد الاختناقات
- **تابع بريد المشتريات** لرصد اتصالات الموردين غير المرتبطة بطلب محدد

---

## القيود المعروفة

- لا يمكن تعديل الطلبات بعد إرسالها للموردين — الحقول الأساسية مقفلة لضمان العدالة
- الطلبات المرسى عليها لا يمكن حذفها — استخدم الأرشفة بدلاً من ذلك
- مطابقة ردود البريد تعتمد على وجود رمز RFQ في سطر موضوع البريد
- يجب إعداد بيانات اعتماد Microsoft Graph API وأن تكون صالحة لعمل ميزات البريد
- قائمة انتظار التسعير الذكي تتطلب مراجعة بشرية قبل تطبيق البيانات المستخرجة
